# Проба: экран утилиты внутри вкладки лаунчера

Среда: macOS 26.2, `swiftc` без Xcode, самоподписанный сертификат без Team ID, hardened runtime, цель 14.2. Окно за экраном: пиксели, клики и ввод глазами не проверены, 14.x и 15.x не проверены.

## ExtensionKit

| Что | Измерено |
|---|---|
| Подпись и отсутствие Team ID | Не мешают; нужен `-e _NSExtensionMain` |
| Расширение отдельного приложения | Код его не видит, пока человек не одобрит в системном интерфейсе: `unapproved 1`, список пуст. Публичного способа из кода нет. Браузер расширений можно встроить в лаунчер |
| Расширение внутри бандла лаунчера | Включено сразу, но тогда экран приезжает с лаунчером |
| Песочница | Обязательна; к воркеру только через `temporary-exception.mach-lookup.global-name`, требование подписи работает |
| Память процесса экрана | 18,4 МБ, CPU в простое 0 % |
| Открытие вкладки | Холодное 170–440 мс, первое после подписи до 680 мс, тёплое 37–55 мс, возврат 3–7 мс |
| Скрытая вкладка | Процесс живёт и рисует, сигнала нет; паузу и выгрузку делает лаунчер |
| Падение | `Code=15`, заглушка, без перезапуска. Зависание: сигнала нет |

Не проверено: сохраняется ли одобрение при обновлении утилиты.

## Вывод

Чтобы вкладки выглядели и работали как сейчас, выбран вариант «экраны в лаунчере, работа в утилитах»: без одобрения на каждую утилиту, без второго процесса на вкладку, без песочницы экрана и с мгновенным переключением. Цена: экран модуля обновляется вместе с лаунчером, а лаунчер получает данные, которые показывает. ExtensionKit остаётся запасным путём, если экраны понадобится выпускать отдельно от лаунчера.
