# Utilitumus

Одно macOS-приложение из системных модулей. Окно с боковой панелью, иконка в Dock. Если закрыть окно, приложение продолжит работать в фоне, выход через Cmd+Q.

## Модули

| Модуль | Статус | Что делает |
|---|---|---|
| Звук | готов | Основной микрофон и основной выход: выбираешь в списке, остальное Utilitumus не даёт выбрать само. По умолчанию — встроенные микрофон и динамики MacBook. Это бывший MicGuard. |
| Нагрузка | готов | Нативный экран: куда уходит память, сессии Claude Code, фоновые агенты. Ничего лишнего ставить не нужно. |
| Стеш программ | готов | Одной кнопкой закрыть отмеченные программы перед игрой и потом вернуть их, а с доступом «Универсальный доступ» ещё и окна на те же места и экраны. |
| Вентиляторы | готов | Аналог Macs Fan Control: кнопка «Полная мощность», режимы Авто / Константа / По датчику для каждого вентилятора, температура процессора и видеокарты. |
| Микшер | готов | Громкость каждого приложения отдельно: список тех, кто сейчас играет, ползунок 0–100 % и «без звука». |
| Мышь | готов | Прокрутка мыши отдельно от трекпада: своё направление («Как трекпад» или «Обратное», отдельно для Magic Mouse) и плавная прокрутка колеса со скоростью и плавностью. Трекпад не трогается. Нужен «Универсальный доступ». |

Новый модуль: case в `Module` (`Sources/App/UtilitumusApp.swift`), экран в `ModuleDetail` и запуск/остановка в `Sources/App/ModuleHooks+Live.swift`. Код модуля лежит в `Sources/Modules/<Имя>/`.

Строка «О проекте» внизу боковой панели открывает страницу с описанием приложения и модулей (это не модуль, в настройках её нет).

### Порядок, скрытие и выключение модулей

У каждого модуля три независимых свойства.

- **Порядок.** Один и тот же в боковой панели и в Настройках. Меняется перетаскиванием: прямо в боковой панели или в «Utilitumus → Настройки…» (Cmd+,), раздел «Модули», за любое место строки. Порядок запоминается; новые модули из будущих версий встают в конец списка.
- **Состояние «Скрыт».** Модуль работает в фоне («Звук» держит микрофон и так далее), но его нет в боковой панели. Скрытые модули собраны внизу панели в строке «Скрытые · N» (она есть, только если такие модули есть): клик по модулю открывает его разово, в контекстном меню — «Показать в панели» и «Выключить модуль». Развёрнут список или свёрнут, запоминается.
- **Состояние «Выключен».** Модуль остановлен полностью и тоже не виден в панели.

Состояния: «Показан» (по умолчанию), «Скрыт (работает в фоне)», «Выключен». Где менять:

- правый клик по модулю в боковой панели: «Скрыть из панели», «Выключить модуль», «Настроить модули…» (откроет Настройки);
- Настройки → «Модули»: у каждого модуля выпадающий список состояния, под списком кнопка «Сбросить порядок и показать всё».

На странице «О проекте» видны все модули. Скрытый подписан «скрыт — работает в фоне» и по клику открывается один раз, состояние не меняется. Выключенный серый, подписан «выключен в Настройках» и не открывается.

Выключенный модуль перестаёт работать в фоне:

- «Звук» перестаёт управлять микрофоном;
- «Вентиляторы» возвращают вентиляторы в «Авто» и перестают их опрашивать и менять;
- «Нагрузка» останавливает свой сервер;
- «Микшер» снимает все тапы, звук приложений возвращается как был;
- «Мышь» снимает перехват прокрутки полностью, прокрутка возвращается к системной;
- «Стеш программ» ничего не слушает; сохранённый стеш остаётся и доступен после включения.

Скрытие на работу не влияет, запуск и остановка происходят только при переходе между «работает» и «выключен». Вернуть модуль можно без перезапуска приложения. Если скрыть или выключить выбранный модуль, откроется первый из показанных. Если в панели не осталось ни одного, окно покажет подсказку с кнопкой «Открыть настройки».

Хранение: порядок в `ModuleOrder` (список id), состояние в `ModuleState.<id>` (`shown` / `hidden` / `disabled`). Прежний флаг `ModuleEnabled.<id> = false` при первом чтении считается «Выключен», всё остальное «Показан».

## Установка

[![Скачать Utilitumus](https://img.shields.io/badge/Скачать-Utilitumus.zip-2ea44f?style=for-the-badge&logo=apple)](https://github.com/IvanSSpace/utilitumus/releases/latest/download/Utilitumus.zip)

Проще всего поставить одной командой в Терминале: она скачает последнюю версию, проверит подпись, положит приложение в «Программы» и запустит его.

```bash
curl -fsSL https://raw.githubusercontent.com/IvanSSpace/utilitumus/main/install.sh | bash
```

Если скачать кнопкой выше, распакуй архив и перетащи `Utilitumus.app` в «Программы». При первом запуске macOS его заблокирует, потому что приложение не подписано сертификатом Apple. Открой его правым кликом и выбери «Открыть», либо сними карантин командой `xattr -dr com.apple.quarantine /Applications/Utilitumus.app`. Команда установки выше этого шага не требует.

Нужна macOS 14.2 или новее на Mac с Apple Silicon.

При первом запуске каждое разрешение даётся один раз: доступ к вентиляторам (пароль), «Универсальный доступ» для стеша и мыши, запись звука для микшера. Обновления подписаны тем же сертификатом, поэтому выданные разрешения после них сохраняются.

## Обновление

Внизу боковой панели показана версия и кнопка проверки обновлений. То же есть в меню «Utilitumus → Проверить обновления…». При запуске приложение само тихо проверяет, есть ли новая версия. Если есть, появляется кнопка «Обновить до …»: приложение скачает релиз с GitHub, заменит себя и перезапустится.

После обновления модуль «Вентиляторы» попросит «Обновить доступ», потому что помощник тоже обновляется.

Выпустить версию: `./scripts/release.sh 0.3.0`. Скрипт соберёт приложение на этом Mac, подпишет его сертификатом «Utilitumus Signing», поставит тег и выложит `Utilitumus.zip` в релиз. Запасной путь — собрать на GitHub: Actions → Release → Run workflow (`.github/workflows/release.yml`).

## Сборка из исходников

```bash
./build.sh
```

Нужны Xcode Command Line Tools. Скрипт собирает `.app` через `swiftc`, подписывает ad-hoc и ставит в `/Applications`.

Иконка генерируется скриптом `swift scripts/make-icon.swift` и сохраняется в `Resources/AppIcon.icns`.

## Автозапуск

```bash
cp local.utilitumus.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.utilitumus.plist
```

При входе в систему приложение стартует с `--background`, то есть в Dock и без окна. Клик по иконке открывает окно.

Отключить: `launchctl bootout gui/$(id -u)/local.utilitumus`

## Нагрузка

Модуль написан на Swift и работает внутри приложения: ни Python, ни веб-сервера, ни отдельных портов. Код лежит в `Sources/Modules/Load/Native/`: память и группы процессов, сессии Claude Code, подсказки, что можно остановить, фоновые агенты и боты. Список ботов читается из `~/Library/Application Support/Utilitumus/bots.toml` (нет файла — нет ботов).

Модуль «Нагрузка» основан на lambscape (MIT, github.com/IvanSSpace/lambscape).

## Доступ к вентиляторам

Читать обороты и температуру можно без прав. Менять обороты SMC разрешает только root, поэтому кнопка «Дать доступ…» ставит помощник `utilitumus-fan` в `/Library/PrivilegedHelperTools/local.utilitumus.fan` (setuid root). Пароль спрашивает сама macOS. Помощник умеет только две команды: `auto <fan>` и `set <fan> <rpm>`, обороты он сам ограничивает пределами вентилятора. Если после пересборки помощник изменился, приложение предложит «Обновить доступ…», а до тех пор продолжит работать со старым.

Защита: выше 95 °C на процессоре вентиляторы отдаются системе, пока не остынет ниже 85 °C. Режим «Полная мощность» это не отключает. При выходе из приложения вентиляторы возвращаются в «Авто». Пока запущен Macs Fan Control, Utilitumus вентиляторы не трогает.

«Максимум в играх» (переключатель под кнопкой «Полная мощность», по умолчанию выключен): когда на переднем плане игра, вентиляторы сами идут на максимум; ушёл из игры — через 60 с вернётся обычный режим, закрыл игру — сразу. Игра — программа с игровой категорией в Info.plist (`public.app-category.*games`) или из списка «Мои игры» (по bundle id, а у процессов без него, например из CrossOver, — по имени исполняемого файла). Лаунчеры (Steam, Epic, Battle.net и др.) по умолчанию не считаются играми, исключение можно снять. Логика лежит в `Sources/Modules/Fans/GameDetection.swift` чистыми типами без AppKit; события пишутся в `~/Library/Logs/Utilitumus/fans.log`.

## Микшер

Для каждого играющего приложения ползунок 0–100 % и кнопка «без звука»; громкость запоминается по bundle id и применяется, когда приложение снова заиграет. Пока у приложения 100 % и звук включён, микшер его не трогает. Как только громкость меняется, Utilitumus перехватывает звук этого приложения через Core Audio process tap и играет его на устройство вывода по умолчанию с нужным множителем. При выходе из Utilitumus все тапы удаляются, и звук возвращается как был.

Нужно разрешение «Запись системного звука»: macOS спросит при первом изменении громкости. Если отказали, включи Utilitumus в «Системные настройки → Конфиденциальность и безопасность → Запись экрана и системного звука → Только запись системного звука».

Принцип (тап → агрегатное устройство → IOProc с усилением) описан в документации Apple и показан в открытых проектах [AudioCap](https://github.com/insidegui/AudioCap) (Guilherme Rambo, BSD-2-Clause) и [Fader](https://github.com/pantafive/fader) (pantafive, MIT). Код модуля (`Sources/Modules/Mixer/`) написан заново по этому принципу, код оттуда не переносился.

## Звук

Микрофон: в списке отмечаешь «Основной микрофон». Если он подключён, он и есть вход. Если нет, входом становится «Микрофон MacBook». Любой другой микрофон, например случайно подключённый провод, сам входом не станет. Для новых установок основной микрофон встроенный. Тумблер «Блокировать Bluetooth-микрофон» закрывает Bluetooth-устройства: они серые с замком и основными быть не могут. Виртуальные устройства (Loopback, Zoom) свёрнуты отдельно и не выбираются; если такое выбрано входом вручную, Utilitumus его не трогает.

Выход: «Основной выход» — «Динамики MacBook» (по умолчанию), любое известное устройство вывода или «Как решит macOS» (не вмешиваться). Если macOS переключила звук на другое устройство, возвращается выбранное. Исключение: Bluetooth и AirPlay, выбранные в системе, не перебиваются, иначе AirPods были бы бесполезны. Если основной выход отключён, звук идёт на динамики MacBook.

Если откатов слишком много за короткое время (3 за 5 секунд, так бывает при звонках, когда macOS временно ставит Bluetooth-гарнитуру), Utilitumus на 25 секунд перестаёт вмешиваться. Вход и выход считаются отдельно.

Логика выбора лежит в `Sources/Modules/Sound/SoundPolicy.swift` чистыми функциями без CoreAudio.

## Переход с MicGuard

При первом запуске настройки MicGuard (приоритет, блокировка Bluetooth, выключенные устройства) копируются из `local.micguard`. Приоритет больше не показывается: основным микрофоном становится верхнее по старому приоритету подключённое устройство, если оно включено галочкой, иначе встроенный. Старый MicGuard нельзя держать запущенным одновременно с Utilitumus: оба будут переключать микрофон.
